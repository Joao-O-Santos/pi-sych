# Project

Keep state explicit and proportionate. User instructions and accepted project
decisions override package guidance; mechanical facts never settle semantic
judgment. Read only canonical files needed for the task. The configured inbox
contains unreviewed proposals; read it only when the user requests inbox review.

Treat authorization at its actual scope. An explicit owner decision or
instruction is accepted unless tentative; inference and agent-proposed durable
state are not. Once a requested task is clearly authorized, carry it through
without asking to continue merely because it is long. Ask only when a new
consequential choice, side effect, or unresolved ambiguity falls outside that
scope. More scrutiny means more checking, not more checkpoints.

Label observations, assumptions, uncertainty, accepted decisions, and unresolved
questions. Create durable state only when it has a real use and is accepted or
explicitly requested. Before an `agents` promotion, require the owner to choose
project or personal scope. Shared conventions belong in the configured project
path; stable private preferences belong in personal Pi instructions. Report only
work actually performed. Read the selected recipe in order.
