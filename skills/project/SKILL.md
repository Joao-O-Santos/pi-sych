# Project

Keep state explicit and proportionate. User and accepted project decisions override package guidance;
mechanical facts never settle semantic judgment. Read configured canonical roles first: `project` for
brief and direction, `evidence` for support and limits, `decisions` for accepted consequential
choices, `agents` for shared operating conventions, `style` for artifact conventions, and `todo` for
unfinished actions. Default installations often map these roles to familiar filenames.

An explicit owner decision is accepted input unless marked tentative; inferences, synthesized briefs,
and agent-proposed durable state require review. Label observation, inference, assumption, accepted
decision, and unresolved question. Do not create files, workflow, or durable state without a real use
and required approval. Before applying an `agents` promotion, require the owner to choose project or
personal scope: shared project conventions belong in the configured project path; stable cross-project
preferences or private tooling belong in personal Pi instructions. Do not infer scope from a
recommendation. Warn that transient preferences, conversation history, and obsolete rules cause
memory rot: stale, conflicting, over-personalized context. Report only work actually performed.

## Choose modules

| If the task is… | Read… |
| --- | --- |
| new or recovered project | `bootstrap` |
| move between state and deliverable | `artifacts` |
| interpret project_status | `status` |
| meaningful disagreement | `reconcile` |
| long or consequential plan | `plans` |
| Pi Sych help | `pi-sych` |
| completed-work lessons | `retrospective` |
