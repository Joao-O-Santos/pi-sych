# Plans

Use the smallest planning depth justified by risk. A plan coordinates work; it
is not automatically a permission gate, and planning remains optional rather
than a mandatory phase. For substantive work, a useful bounded loop is:
brief → explore or structure → build → targeted review when justified →
integrated response → revise → verify → meaningful state update. Do not force
every phase on simple reversible work or turn the loop into a controller.
When findings interact, choose
one integrated response, state implementation order and global constraints, and
identify suggestions deliberately not adopted. Prefer a simple coherent revision
over locally optimal changes that sprawl.

Keep the plan conceptual and small: outcome, constraints and
non-goals, relevant dependencies and context, unresolved
consequential choices, verification, and next work.

Choose execution by the current task and context needs rather than a fixed
default. A clean worker is appropriate when an explicit packet is sufficient;
use trajectory context when prior conversation materially helps. Supervisor
pre-work recorded in a plan, TODO, brief, or context file can make a clean
worker packet sufficient.

A decision memo may state options, evidence, trade-offs, unresolved questions,
and the owner decision. If a consequential choice is still unresolved, stop at
that choice. A plan file records intent and coordination; file existence alone
does not prove authorization.
