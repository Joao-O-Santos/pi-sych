# Bootstrap

Read applicable shared `agents` instructions, the configured project brief,
relevant artifacts, project memory, and Git evidence before interviewing or
refreshing. Inspect what already exists, then ask only for information whose
absence prevents useful work or would materially change the project. Establish
objective, audience, contribution, deliverable, constraints, and completion
criteria without exhausting a questionnaire. Stop interviewing once useful work
can begin.

Separate direct observations, bounded inferences, and unresolved questions; use
`{accepted}`, `{provisional}`, `{inferred}`, or `{unresolved}` when briefing. An
explicit owner decision is accepted unless tentative. Inferences and proposed
durable state remain proposals. Workers may propose updates; only the supervisor
writes the canonical brief.

Propose only useful canonical roles—`project`, and when needed `style`,
`evidence`, `decisions`, or `todo`—plus `SYNC.json`; use configured paths, not
assumed filenames. Synchronization records reviewed content and dependencies;
it neither proves truth nor resolves disagreement.
