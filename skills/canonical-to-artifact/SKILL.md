# Canonical state to artifact

Read `PROJECT.md`, relevant `EVIDENCE.md` entries, `SYNC.md`, and optional project decisions or style before drafting.

For every outline or section candidate, state:

- the project constraints used;
- evidence entries or source paths used;
- unresolved assumptions or missing support;
- dependent artifacts that may become stale if the proposal is accepted.

Do not claim that a project statement, evidence entry, or inference has been accepted merely because it appears in a candidate. Drafting is a proposal until the user approves the durable changes. Use artifact-specific skills for prose, methods, code, slides, or analysis rather than creating a second orchestration workflow.

## Optional user examples

If `~/.config/pi/skills/canonical-to-artifact/examples.md` exists, read it before applying this skill. Use it as illustrative preference, not as evidence or project requirements.
